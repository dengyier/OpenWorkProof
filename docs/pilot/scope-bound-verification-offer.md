# OpenWorkProof 21 天范围可验证交付付费试点

> 当前状态：商业方案已形成；外部报价、定金、客户验收、续费、上游采用与
> 正式部署均为 `not evidenced`。本文是验证假设与执行边界，不是成交证明。

## 1. 用户、付费方与验收权威

| 项目 | 首轮假设 | 当前证据 |
|---|---|---|
| User | Agent/AI 方案商的交付负责人、质量负责人、项目经理 | `not evidenced` |
| Payer | 因验收争议、补证成本和回款不确定性承担损失的方案商负责人或交付总监 | `not evidenced` |
| Customer Acceptor | 客户书面指定、密钥独立于交付团队的验收负责人 | `not evidenced` |
| 首个场景 | 一项有明确代码 revision、必选测试、交付物和验收条件的 Agent 项目 | `not evidenced` |

方案商是首要付费方假设，因为它控制交付流程、直接承担返工与回款周期，并
可以把可离线复核的 Scope Coverage Report 作为客户验收材料。客户是否愿意
直接付费，是第二阶段假设，不能在首单前写成事实。

## 2. 试点交付物

1. 一份双方确认的 SubjectClaim：主张、必选工件、验收条件与排除项；
2. 一份 Manager 签名 Evaluation Scope：source/candidate revision、selector、
   文件、测试、必选目标与 population digest；
3. 一组固定 Verification Profile：正臂、真实负控、命令、依赖与执行边界；
4. 正负臂签名结果、Observed Scope、原因码与 Verification Decision；
5. `public`、`diagnostic`、`customer_private` 三种交付包；
6. 一份买方可读 Scope Coverage Report 与离线复核说明；
7. 一次 Customer Acceptor 复核会和一份技术/商业复盘记录。

`READY_FOR_ACCEPTANCE` 只表示材料可以提交验收，不表示客户已验收或已经付款。

## 3. 正式商业字段

| 字段 | 要求 | 当前值 |
|---|---|---|
| 报价主体 | 成都星火领航科技有限公司或经双方书面确认的签约主体 | `not evidenced` |
| 正式报价金额（含税） | 在 SOW 中填写固定人民币金额 | `not evidenced` |
| 启动定金/retainer | 在 SOW 中填写金额、比例、收款条件与凭证引用 | `not evidenced` |
| 尾款条件 | Customer Acceptor 收到约定交付物；是否接受由其独立决定 | `not evidenced` |
| 付款凭证 | 银行/支付机构凭证的外部引用，不写入公开包 | `not evidenced` |

没有可定位的正式报价和定金凭证时，只能说“正在验证付费假设”。会议兴趣、
GitHub Star、技术测试通过和离线包通过都不等于商业验证。

## 4. 21 天执行与资源上限

| 时间 | 工作 | 通过条件 |
|---|---|---|
| Day 1–3 | 确认 User/Payer/Acceptor、SOW、报价、定金要求、主张与排除项 | 责任人明确；没有团队代填客户权威 |
| Day 4–7 | 冻结 Scope、selector、必选目标、正负臂和环境 | Scope 可重算；负控能反证主张 |
| Day 8–14 | 执行、提交签名结果、形成 Decision 和三种包 | 缺证据即 UNKNOWN；篡改失败关闭 |
| Day 15–18 | Customer Acceptor 独立复核和补证 | 有签名决定，或如实记录 `not evidenced` |
| Day 19–21 | 商业复盘、回款证据、下一单判断 | 技术结论与付款结论分别记录 |

- 外联目标最多 5 家；超过 5 家前先复盘拒绝原因；
- 团队投入上限 8 人日；
- 工具、云资源与材料实验支出上限人民币 2,000 元；
- 从第一封正式定向邀约起 21 天内结束本轮，不无限延长“试用”。

## 5. 成功、继续与停止规则

**商业成功信号**：至少一家目标客户/方案商签署明确 SOW，并支付可定位的
启动定金。只有材料存在后，付费状态才可从 `not evidenced` 更新。

**技术成功信号**：客户定义的必选目标进入签名 Scope；正臂与负臂在同一
人口上可重放；第三方从客户私有包得到同一有边界结论；单字节篡改失败关闭。

**继续条件**：商业成功信号成立，或目标方给出有责任人、日期和书面采购
路径的明确下一步，且未突破资源上限。

**停止/重构条件**：21 天内无定金；无法获得独立 Customer Acceptor；业务
意图无法转写为可验证条件；五家目标的共同拒绝指向低价值；或预计投入将
超过 8 人日/2,000 元上限。停止不等于协议失败，而是当前用户、付费方或
场景假设未获验证。

## 6. 对外声明边界

OpenWorkProof 不托管资金，不执行付款，不自动结算，不替代法律审计，也不
证明未编码的业务意图、普遍正确性或法规合规。MCP/A2A 提供互操作与消息、
身份、安全和任务能力；本试点只增加一次交付的授权、范围、执行证据和验收
依据。所有外部结果在获得可定位材料前保持 `not evidenced`。
