## 4. 新增产品级修复(本轮发现并修复)

M2 首次将 `repo_read` 与 `apply_patch` 放在同一条链上(repo_read 在前,
apply_patch 在后),暴露出因果回放的一个真实缺口:

- **问题**:发布层要求新收据的 tip(此处为 repo_read)出现在
  `parent_receipt_ids` 中;但 `composition.py` 的精确因果回放对
  `owp.apply_patch` 只要求 grant issuance 一个语义父,导致
  "receipt causal parents failed exact historical replay"。
- **修复**:`src/openworkproof/composition.py` 在 ToolCallReceipt 分支为
  `owp.apply_patch` 增加规则:若同一 grant 上存在先前 repo_read,则该
  repo_read 作为 apply_patch 的语义父(镜像发布层 tip-parent 规则)。
- 该修复与既有链兼容:apply_patch 之前没有 repo_read 的链(全部既有测试)
  行为不变;只有 repo_read → apply_patch 的组合新增一个语义父。
