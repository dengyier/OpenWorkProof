## 3. 核心主張

> 我們不假設 Agent 永遠不逃逸，而是讓逃逸後的每一步都無法偽造、無法越權、無法抹去。

- 痛點：AI Agent 逃逸
- OWP 的角色：每一個 Agent Decision 都加上 Agent Sign，降低逃逸後的風險（assume breach）
- 坦白限制：簽名只證明「誰、什麼範圍、做了什麼」，**不能阻止已被攻破的 Agent 在授權範圍內作惡**，風險取決於授權範圍、高風險是否一律人批、異常能否快速撤銷

## 4. 總架構（由外到內）

1. **入口網關**：單向、只讀、限速、僅送特徵窗口；先記錄後轉發；帶監控與審計
2. **隔離沙箱（管理域 A）**：特徵提取 → 雙模型推理 → 判定 → 標準化輸出；最低權限
3. **唯一通道**（vsock）→ **受控出口代理**：限流、會話控制、先記錄後轉發
4. **Agent Sign 簽名服務**：私鑰在 HSM、沙箱外；每個決策單獨簽名、單次、短時效、綁定範圍
5. **策略執行點**：驗簽、範圍、nonce、時效、撤銷
6. **風險分級**：低風險在限定範圍內自動執行；疑似零日與出站連線必須人工簽名
7. **出站網關**：預設拒絕、限流、單次限時放行；顯示目的 IP／埠／公網或私網
8. **OWP 帳本**：決策、Agent Sign、人工簽名、結果（只增不改）
9. **日誌與審計域（獨立管理域 B）**：集中日誌、只增存儲、時間同步、哈希錨定、異常監測與撤銷金鑰／冻結沙箱

### 逃逸後的權限（最低權限）
| 項目 | 內容 |
|---|---|
| 只有 | 讀只讀模型、讀特徵窗口、寫輸出到唯一通道 |
| 沒有 | 私鑰、訓練數據、標籤、其他網絡、宿主文件、寫模型、改配置 |

### 沙箱實作要點
- 非 root、唯讀檔案系統、seccomp；僅留 vsock，不給網卡
- 建議 microVM（Firecracker／Kata）或 gVisor，普通容器隔離不夠
- 不放任何憑證與環境變數；DNS 也要走攔截層
- 已知風險：模型檔在沙箱內，可能被竊取或反推

## 5. 雙模型檢測

### 訓練域（離線、與沙箱無直連）
```
數據採集與標註 → 數據校驗與清洗 → [已知攻擊模型 | 異常檢測模型]
→ 對抗與穩健性評估 → 模型登記 + 簽名 → 模型發布閘門（驗簽、驗哈希、人工批准）
```
- **已知攻擊模型**（監督）：輸出類別 + 校準後置信度；低置信或不屬任何類別時輸出「未知」
- **異常檢測模型**（無監督）：只用乾淨正常流量（自編碼器）；閾值取驗證集 99.5 分位；按服務／主機群分別建基線
- **疑似零日判定**：已知置信度低 **且** 異常分數高
- **評估**：「留一個攻擊家族」不參與訓練，測檢出率；同時統計每日誤報數
- **回饋**：分析師標籤須人工審核後才進訓練集（防投毒）

### 標準化輸出欄位
```json
{
  "known": {"class": "none", "attack_technique": null, "confidence": 0.31},
  "anomaly": {"score": 0.97, "threshold": 0.90, "top_features": ["..."]},
  "verdict": {"suspected_zero_day": true, "rule_version": "zd-rule-1"},
  "models": {"known_sha256": "<hash>", "anomaly_sha256": "<hash>", "dataset_sha256": "<hash>"}
}
```

## 6. 證據包與簽名流程

```json
{
  "schema": "aisoc.zeroday.evidence/0.1",
  "case_id": "ZD-2026-000123",
  "verdict": "suspected_zero_day",
  "evidence_refs": [{"type": "pcap", "uri": "evidence/ZD-123/flow.pcap", "sha256": "<hash>"}],
  "recommended_action": "quarantine",
  "agent_signature": "<sig>"
}
```

1. 以 JCS（RFC 8785）規範化後簽名（Ed25519）
2. 大檔案只放哈希與路徑，證據存唯讀儲存（WORM）
3. 分析師決定引用 `case_id` 與證據包哈希，再簽一份
4. 執行前驗證：雙簽名有效、哈希相符、在授權範圍內（目的地、TTL、單次使用）
5. 帳本為哈希鏈，定期錨定外部時間戳；驗證器可離線執行

## 7. 標準對照

### CISSP 概念（未綁定特定版本）
| 原則 | 對應設計 |
|---|---|
| 問責性 | 每個出入口可追溯到身份與動作 |
| 完整中介 | 所有跨邊界流量必經閘門，無旁路 |
| 深度防禦與職責分離 | 日誌域獨立，沙箱管理員改不了日誌 |
| Fail-secure | 日誌失效即阻斷，不放行 |
| 日誌完整性 | 只增不改、時間同步、哈希鏈 |

### NIST／OWASP／MITRE
- **NIST AI 100-2 E2025**（目前最新版）：投毒 → 數據校驗；規避 → 對抗評估；隱私／模型竊取 → 沙箱內推理
- **NIST AI RMF**：模型發布閘門對應 Manage／Govern
- **OWASP ML Security Top 10**：圖上標了「供應鏈」「輸出完整性」（條目名稱未核對最新版）
- **MITRE ATT&CK**：已知模型輸出技術 ID；零日標「未映射」由人工補；ATLAS 用於模型自身威脅建模

### 國內規範（信通院 2026 年 9 月報告等）
- 智能體三層框架：基礎層（身份）、運行層（日誌、熔斷、一鍵關停）、生態層（責任按控制力分配）
- 《智能體規範應用與創新發展實施意見》：三種決策模式（僅限本人／需授權／智能體自主）
- GB/Z 185—2026 智能體互聯系列；網絡安全法修訂自 2026-01-01 施行

## 8. 監管沙盒方案（摘要）

- 目標：在受控環境驗證「AI 偵測 → 簽名證據 → 人工簽名決策」是否同時安全、可問責、不拖慢處置
- 三階段：影子模式（只建議）→ 雙簽模式（零日必須人簽）→ 達標才逐步擴權
- 指標：誤報率、人工覆核時長、覆寫率、簽名驗證通過率、竄改檢出率；任一超標回退上一階段
- 對抗測試：日誌內藏惡意指令（prompt injection）、基線投毒、偽造簽名、竄改證據、批准過快（橡皮圖章）、重放
- 監管者價值：帳本只存哈希，用公鑰離線驗證，不必接觸原始流量

## 9. 創新點（主打三個）

1. 把「AI 自主權邊界」變成可驗證的密碼學記錄（AI 簽名 + 人簽名 + 可離線驗證帳本）
2. 沙箱內 Agent 不持有私鑰，逃逸也偽造不了責任鏈
3. 用「留一個攻擊家族」量化零日偵測能力

次要亮點：出站連線單次限時、日誌寫不進去即阻斷、防橡皮圖章。
注意：不要說「首創」，說「補上業界在可驗證問責上的缺口」。

## 10. 業界現況（摘要）

- 自主度按動作分級，高影響動作需人批准，低風險可自動
- 人在迴路中（每步批准）與人在迴路上（策略監督）並用
- 缺口：審計證據模板未統一；agent 步驟間上下文、提示、閾值、政策檢查常不入日誌
- 多數資料來自廠商文章，數字僅供參考
